# qsel_core — 고정 생성기 + Q 선택 + 손 좌표계 보정기 + 정지 종료 규칙 (핵심 코드)

체크포인트·데이터는 들어 있지 않습니다. 실로봇에서 Q와 잔차(보정기)를 **다시 학습**하는 것을 전제로, 실행·학습 로직만 모았습니다.
원본은 시뮬레이터(manifeel / Isaac Gym, 키 USB 삽입) 실험 코드이며, 파일 안의 절대 경로(`/home/dyros-recruit/...`)는 새 환경에 맞게 바꿔야 합니다.

## 구조 한눈에

```
매 12 스텝(refresh)                                   매 스텝
┌──────────────────────────────────────┐            ┌───────────────────────────────────────────┐
│ 생성기: LDP(latent diffusion) → 후보 16개 │            │ 보정기(잔차): 생성기 action + δ            │
│        AT 디코더(촉각으로 재디코딩)        │            │  x,y : 보정량 (hand frame, ±0.2)          │
│ Q (IQL 앙상블 9개): 후보 점수              │──선택──▶   │  rz  : 크기 = 잔차 |rz|, 방향 = sign(−ê)  │
│ 정지 규칙: 정지 2회 연속 전에는 "유지" 후보만 │            └───────────────────────────────────────────┘
└──────────────────────────────────────┘
정지 = 24 스텝 손 이동 < 3 mm. 손이 다시 움직이면 정지 카운트 리셋.
전환 후보 = 지난 24 스텝 명령과의 정규화 평균 차이 > 1.0 (Otsu θ).
```

| 파트 | 역할 (option 해석) |
|---|---|
| 생성기 (LDP + AT) | option 후보 |
| 보정기 | 모드 시험 (맞는 모드면 국소 오차를 고쳐 진행) |
| 보정기를 켠 상태의 정지 | option 종료 |
| Q | 다음 option 선택 |

## 실로봇 보정기 계획 (11-18, 미검증)

> 첫 실로봇 과제는 multisocket. 단계·수량·실행 프로그램 수정점·확인 필요 항목은 [`REAL_ROBOT_MS_PLAN.md`](REAL_ROBOT_MS_PLAN.md).

전제: 소켓 위치는 수집 중 무작위, 외부 카메라 없음(손목 카메라 + 촉각 + 기구학), 임피던스(순응) 제어.

### 보정기 구성

| 축 | 크기(언제·얼마나) | 방향 | 라벨 출처 |
|---|---|---|---|
| x, y, rz | 잔차 | 오차 헤드 sign(−ê) (ER3 확장) | 잔차: 사람 교정 / 오차 헤드: 역방향 수집 |
| z | 잔차 | 잔차 (누르기·들기가 상황마다 달라 오차 헤드 없음) | 사람 교정 |
| rx, ry | 잔차 | 잔차 | 사람 교정 |

- **z를 포함하는 이유**: 실물에서는 누르며 비틀기, 살짝 들었다 다시 누르기 같은 회복 동작이 필요할 가능성이 큼. 시뮬레이터 교사는 z 라벨이 항상 0이었고(사실상 z 없음), ER3 실패 75개 중 순수 z 부족은 약 2개였지만 이는 깔끔한 시뮬레이터 접촉 때문일 수 있음.
- 바탕 제어: 임피던스 순응(z 강성 낮게), 선택적으로 InsertionNet식 힘 항 δz = −c(f_목표 − f_z) (학습 없음).

### 라벨: 사람 교정 vs 역방향 수집

| | 사람 교정 (CR-DAgger식) | 역방향 수집 (InsertionNet식) |
|---|---|---|
| 라벨 | 생성기 명령 대비 보정 (**상대값**) | 구멍 대비 현재 오차 (**절대값**) |
| 축 | 6축 모두, 회복 동작 포함 | x, y, yaw |
| 정밀도 | 1° / 1 mm 이하는 사람이 보기 어려움 | 로봇이 만든 δ를 관절값으로 앎 |
| 비용 | 매 에피소드 사람 필요 | 자동 (끝까지 꽂은 자세 = 0 기준, 알려진 오프셋 δ로 빼고 다시 접근) |

- 시뮬레이터 근거: 지금 잔차는 사실상 완벽한 상대값 교정으로 학습했는데도 rz 방향 일치 0.47(무작위 수준). 같은 데이터에서 목표를 절대 오차로 바꾼 오차 헤드는 0.79, 폐루프 +8.3%p (ER3). 사람 교정만으로는 "언제·얼마나·회복 동작"은 배우지만 "어느 쪽으로"는 약할 가능성이 큼.
- 성공 순간 손 yaw 기준(되짚기) 라벨은 부족: 성공 에피소드만 라벨이 생겨 크게 틀린 정지 상태가 빠지고, 기준 편향 중앙값 1.6°. 접촉 중 손 안 플러그 회전이 있으면 기구학 추적도 끊김.
- 오차 헤드에 필요한 정밀도(시뮬레이터 잡음 주입): 에피소드 단위 편향 σ ≤ 0.5°, 스텝 잡음 ~1°까지 허용.
- 역방향 수집의 전제(실로봇에서 먼저 확인): 꽂힌 상태의 yaw·xy 유격이 작을 것, 뽑는 동안 손 안에서 플러그가 돌지 않을 것.

### 순서

1. **사람 교정만으로 6축 잔차 학습** (기준선). 교정이 없는 곳은 라벨 0 → 암묵적 게이트.
2. 학습 점검: 검증 데이터에서 축별 "예측 크기 / 라벨 크기" 비율 (시뮬레이터에서 MSE가 크기를 1/10–1/20로 줄임).
3. rollout 진단 지표 기록: "키 방향 맞은 채 입구 정지 → 전환" 비율 (시뮬레이터 잘못된 회전 10개가 전부 이 경로, xy 0.4–1.1 mm 어긋남).
4. 3이 잦으면 **역방향 수집 → 오차 헤드 → x, y, rz 방향 교체** 추가.

### z를 넣을 때 정할 것

- **정지 판정**: 지금 정지 = 24 스텝 손 이동 < 3 mm. 잔차 z가 들었다 놓으면 막혀도 리셋되어 모드 종료가 늦어짐 → 잔차 몫을 뺀 이동, 또는 비율형 정지(실제 이동 / 생성기 명령 이동)로 측정.
- **안전**: 잔차 z는 비대칭으로 자름(내리기 작게, 들기 크게). 힘 상한은 임피던스 강성으로.
- **크기 축소**: z 회복 동작은 짧고 드물어 0으로 학습될 위험 → 교정 구간 가중치 또는 크기·방향 분리.

## 실로봇으로 옮길 때 바꿔야 하는 것

1. **보정기 라벨**: `delta_residual_gatefree_20261106.py`의 교사는 시뮬레이터 특권 정보(구멍·플러그 자세)를 씁니다. 실로봇에는 없습니다.
   - 위 "실로봇 보정기 계획" 절 참고: 잔차 6축(z 포함)은 사람 교정, x·y·rz 방향(오차 헤드)은 필요 시 역방향 수집.
2. **Q 데이터**: 실로봇 자율 rollout(후보 중 실행된 것 + 성공 보상). 시뮬레이터 결과상 약 400 runs 미만에서는 Q가 오히려 해로움(200 runs: Q 없음보다 −3.5%p) → 데이터가 적을 때는 확신 낮은 전환 억제 필요.
3. **정지 규칙 상수**: 24 스텝 / 3 mm는 시뮬레이터 제어 주기 기준. 실로봇 제어 주기·임피던스에 맞게 재보정. 잔차에 z를 넣으면 측정 방식도 바꿀 것(위 절).
4. 절대 경로, wandb 프로젝트명, 포트 번호.

`robot_command_sent: false` — 이 코드는 시뮬레이터에서만 검증되었습니다.
