# 실로봇 실행 프로그램 (2026-11-16 초안, 11-19 갱신)

## 11-19 변경 (실로봇 multisocket 계획 반영, `qsel_core/REAL_ROBOT_MS_PLAN.md`)

| 무엇 | 전 | 후 |

| 시험 | — | `test_realrobot_20261119.py` (CPU, 체크포인트·로봇 없음): ER3 부호, 자르기, 좌표 변환, 성공 후 정지, 가짜 로봇 루프, 정면 없는 기록, 방식 표 |

아직 안 한 것: stallr 기반 `PolicyCore`로 시뮬레이터 결과 재현 확인 (GPU), `FrankaRobot` (제어기 정보 대기), 실데이터 잔차·오차 헤드의 입력 함수 (`feat`), 손목 단독 생성기 설정.


시뮬레이션에서 쓰던 정책(생성기 + Q selector + 믿음 규칙 + 연속성 항 + residual)을 실로봇 시간 조건에서 돌리기 위한 코드.
선택 계산은 시뮬레이션 서버(`policy_server_selrule_xfade_20261116.py`)의 함수를 그대로 불러 쓴다.
아직 로봇에 명령을 보낸 적 없음 (robot_command_sent: false).

## 파일

| 파일 | 하는 일 |
|---|---|
| `policy_core.py` | 정책 계산. `plan()` 후보 16개 생성 + Q 채점 + 믿음 규칙, `decode()` 매 스텝 명령, 관측·이력 버퍼 |
| `runtime.py` | 시간 관리. 12스텝마다 계획 요청, 2스텝 뒤 교체(지연 맞춤), 교체 직후 K스텝 섞기, residual 더하기, 기록. `realtime=True`면 계획을 뒤 스레드(별도 CUDA stream)에서 계산하고 제어 루프는 기다리지 않음 |
| `rr_server.py` | 정책 프로세스. 한 스텝에 메시지 하나(관측 → 명령). 로봇 제어 프로세스와 분리 |
| `robot_iface.py` | 로봇 인터페이스 규약, 하드웨어 없는 `FakeRobot`, 제어기 요구 사항을 적은 `FrankaRobot` 자리 |
| `xela_c8d.py` | XELA uSPA44 16칸 × 3축 → 촉각 8값. 원래 uSPA44 계산식과 같음. 영점 잡기 포함 |
| `recorder.py` | 에피소드 기록(npz)과 학습용 zarr 변환 |
| `teleop_spacemouse.py` | 3D 마우스 → 스텝 명령. 불감대, 축 맞춤, 넘겨받기 버튼 |
| `timing_test.py` | 하드웨어 없이 실시간 모드의 시간 측정 |

## 한 스텝의 흐름

1. 관측 읽기 (카메라 2대, 손 자세, 촉각 8값)
2. 12스텝마다 계획 요청 (실시간 모드는 뒤 스레드)
3. 새 계획이 준비됐고 관측 후 2스텝 이상 지났으면 교체
4. 현재 계획을 지금 촉각으로 풀어 명령 계산. 교체 직후 K스텝은 이전 계획과 섞음
5. residual 보정 더하기
6. 명령 전송 (명령 단위: 이동 10 mm, 회전 0.05 rad / 스텝)

## 실로봇 전에 바꿔야 하는 것

- residual: 지금 것은 시뮬레이션 촉각(10×14) 입력. XELA 4×4 입력으로 다시 학습해야 함.
- 정책 전체: 실로봇 데이터로 다시 학습. 촉각 8값의 정규화도 실데이터 기준.
- 손 자세의 쿼터니언 순서와 부호를 학습 데이터와 맞출 것.
- 카메라 영상: RGB, 256×256, 0~1 실수, 노출 고정.
